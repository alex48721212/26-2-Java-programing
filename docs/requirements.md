# 요구사항 명세서 — 회사 연차관리 시스템

## 1. 개요
직원의 입사일과 근태 기록을 바탕으로 회계연도마다 연차를 자동 부여하고,
연차 신청·승인·반려·취소와 잔여 연차 관리를 수행하는 Java 콘솔 프로그램이다.

## 2. 사용자(액터)
| 액터 | 설명 | 주요 권한 |
| --- | --- | --- |
| 직원(사원) | 일반 사원 | 연차 신청, 본인 신청 취소, 본인 연차·신청 내역 조회 |
| 팀장 | 소속 팀원의 결재권자 | 직원 권한 + 팀원 신청 승인/반려 |
| 관리자 | 인사 담당 | 직원 등록, 결근 등록, 연차 일괄 부여, 통계 조회 |

## 4. 연차 계산 규칙 (근로기준법 제60조 기반, 회계연도 기준으로 단순화)

### 4-1. 기본 원칙
- 부여 기준: 회계연도(매년 1월 1일) 일괄 부여
- 출근율 = (소정근로일 − 결근일) / 소정근로일
    - 소정근로일: 해당 기간의 평일 수 (공휴일 미고려)
- 개근: 해당 월의 결근일이 0일
- 근속연수: 1월 1일 시점에 입사일로부터 만 몇 년인지
- 모든 일수는 0.5 단위로 관리한다.

### 4-2. 부여 규칙
| 구분 | 조건 | 부여 연차 |
| --- | --- | --- |
| 입사 첫해 | 입사 후 1개월 개근할 때마다 | 1일씩 발생, 최대 11일 |
| 입사 다음 해 1월 1일 | 전년도 출근율 80% 이상 | 15 × (전년도 재직일수 / 365), 0.5 단위 올림 |
| 2번째 1월 1일부터 | 전년도 출근율 80% 이상 | 15 + (근속연수 − 1) / 2 (정수 나눗셈), 최대 25일 |
| 2번째 1월 1일부터 | 전년도 출근율 80% 미만 | 전년도 개근한 달 수 × 1일 |

### 4-3. 근속연수별 부여 일수 (출근율 80% 이상)
| 근속연수 | 부여 연차 |
| --- | --- |
| 1~2년 | 15일 |
| 3~4년 | 16일 |
| 5~6년 | 17일 |
| 7~8년 | 18일 |
| 9~10년 | 19일 |
| 11~12년 | 20일 |
| 13~14년 | 21일 |
| 15~16년 | 22일 |
| 17~18년 | 23일 |
| 19~20년 | 24일 |
| 21년 이상 | 25일 (상한) |

### 4-4. 계산 예시
- 2026-07-01 입사, 2026년 결근 없음
    - 2026년: 매월 개근 시 1일씩 발생 (최대 11일)
    - 2027-01-01: 재직 184일 → 15 × 184 / 365 = 7.56 → 0.5 단위 올림 → 8.0일
- 2020-03-01 입사, 전년도 출근율 90% → 2027-01-01 근속 6년 → 17일
- 2020-03-01 입사, 전년도 출근율 70%, 개근 월 8개 → 8일

## 5. 연차 종류
| 종류 | 차감 단위 | 잔여 차감 | 비고 |
| --- | --- | --- | --- |
| 연차 | 1.0일 × 일수 | 차감 | |
| 오전 반차 | 0.5일 | 차감 | 시작일 = 종료일 |
| 오후 반차 | 0.5일 | 차감 | 시작일 = 종료일 |
| 병가 | 1.0일 × 일수 | 차감하지 않음 | 신청·승인 절차는 동일하게 거친다 |

## 6. 신청 상태 규칙
| 현재 상태 | 동작 | 수행자 | 다음 상태 |
| --- | --- | --- | --- |
| (신규) | 신청 | 직원 | 대기 |
| 대기 | 승인 | 신청자의 팀장 | 승인 (병가 외에는 잔여 연차 차감) |
| 대기 | 반려 | 신청자의 팀장 | 반려 |
| 대기 | 취소 | 신청자 | 취소 |
| 승인 | 취소 | 신청자 | 취소 (병가 외에는 잔여 연차 복구) |

**불가능한 동작**
- 반려·취소 상태의 신청은 어떤 동작도 할 수 없다.
- 승인된 신청은 다시 승인하거나 반려할 수 없다.
- 본인 신청은 본인이 승인할 수 없다.
- 팀장은 본인 팀원이 아닌 직원의 신청을 처리할 수 없다.
- 사원 직급은 결재할 수 없다.

## 7. 검증 규칙
- 시작일은 종료일보다 뒤일 수 없다.
- 시작일이 오늘 이전인 신청은 할 수 없다. (오늘 날짜는 허용)
- 반차는 시작일과 종료일이 같아야 한다.
- 신청 일수가 잔여 연차보다 많으면 신청할 수 없다. (병가 제외)
- 승인 시점에 잔여 연차가 부족하면 승인할 수 없다. (병가 제외)
- 입사일은 미래일 수 없다.
- 결근일은 입사일 이전이거나 미래일 수 없고, 같은 날짜는 중복 등록되지 않는다.
- 이름은 비어 있을 수 없다.

## 8. 비기능 요구사항
- 콘솔(Scanner) 기반으로 동작한다.
- 데이터는 메모리에 저장한다. (프로그램 종료 시 사라짐)
- 잘못된 입력이나 규칙 위반 시 오류 메시지를 출력하고 메뉴로 돌아간다.
- 도메인 규칙은 JUnit 5 단위 테스트로 검증한다.
- 저장 방식은 Repository 인터페이스 뒤에 숨겨 교체 가능하게 한다.

## 9. 설계 결정
| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 부여 기준 | 회계연도(1월 1일) 일괄 부여 | 실제 회사에서 관리 편의상 가장 많이 쓰는 방식 |
| 출근율 반영 | 반영 (개근 가정하지 않음) | 근로기준법 규칙을 그대로 따르기 위해 |
| 연차 단위 | double, 0.5 단위로만 사용 | 0.5는 이진수로 오차 없이 표현되어 계산 오류가 없음 |
| 비례 부여 소수점 | 0.5 단위 올림 | 근로자에게 유리한 처리이며 반차 단위와 일치 |
| 병가 | 잔여 연차 미차감 | 연차와 별개의 휴가로 처리 |
| 신청 시작일 | 오늘 이전 불가, 오늘 허용 | 당일 반차 사용을 허용하기 위해 |
| 직급 | 사원 / 팀장 / 관리자 (enum) | 결재 권한 구분에 충분 |
| 저장 방식 | Repository 인터페이스 + 메모리 구현 | 추후 파일/DB로 교체 가능 |
